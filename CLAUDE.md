## IC consistency rule (read first)

The outcome for every session: work stays consistent with the current
Decisions Register and canon, and says which source it rests on.

**Before changing or answering anything about IC structure, doctrine or progression, read in this order:**
1. The Decisions Register: `ic-canon/docs/ic-harness/register.md`
   (a copy of the Claude Doc master, which is the source). Check its date and
   last entry against the range the Project Briefing §0 gives for the register.
   If the copy is behind, say so and treat any ruling after its last entry as
   unverified; don't guess.
2. Structural canon: `ic-canon/canon/`.
3. Relevant canon prose: bedeplex-wiki `claude/*.md`.
4. The Project Briefing, §7 (Superseded — do not use).
5. Open Brain last, only for what the above don't cover.

**Open Brain hits are leads, not facts.** It ranks by similarity, not date.
Old vault notes (BeneGame/BedeGame users' manual, 2021–22 material) and
superseded terms (BeneGame, School, students, Modes, sub-rooms, CH,
frontier room, Deanery for a Hall's centre, the Artyst as an IC surface)
must be checked against the register before use.

**Cite.** Name the register entry or canon file a change rests on
(e.g. "per D-76") in the commit message or report. If none exists,
the idea isn't ruled: stop and report rather than build it.

**Never record a ruling from a session.** Rulings are made in chat and
entered in the register by Matthew. If work reveals a conflict between
the register, canon and code, stop and report it.
